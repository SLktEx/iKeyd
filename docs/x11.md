# X11 backend

`iKeyd.X11` combines the shared Linux input layer with X11-specific desktop integration.

## Architecture

```text
physical keyboard
    │
    ▼
iKeyd.Linux (evdev + EVIOCGRAB)
    │
    ├── Core remapping / chords / modes
    │
    ▼
uinput virtual keyboard

X11 DISPLAY
    ├── EWMH / Xlib: windows, focus, geometry, state, work area
    ├── XTEST: absolute pointer, mouse buttons, wheel
    └── xclip: CLIPBOARD selection read/write/watch
```

Global keyboard suppression is intentionally implemented through the same evdev/uinput layer used by Wayland. This avoids an X11 keyboard-grab/reinjection loop and keeps Linux physical-input behavior identical across both Linux backends.

## Requirements

Global keyboard remapping requires read access to the selected `/dev/input/event*` keyboard devices and write access to `/dev/uinput`. Configure those permissions with normal udev/group policy rather than making devices world-readable/writable.

The shared Linux input layer auto-discovers keyboards through `/dev/input/by-id/*-event-kbd` and `/dev/input/by-path/*-event-kbd`. Override it with:

```bash
export IKEYD_INPUT_DEVICES=/dev/input/event3:/dev/input/event6
export IKEYD_UINPUT=/dev/uinput
```

X11 desktop integration requires a usable `DISPLAY`. Clipboard integration additionally requires `xclip`.

## X11 capabilities

The compositor/window-manager-independent X11 backend implements:

- active window lookup (`_NET_ACTIVE_WINDOW`),
- top-level client enumeration (`_NET_CLIENT_LIST`),
- current work area (`_NET_WORKAREA`),
- window geometry and move/resize,
- window activation/focus,
- minimize, maximize and restore,
- always-on-top through `_NET_WM_STATE_ABOVE`,
- opacity through `_NET_WM_WINDOW_OPACITY`,
- absolute and relative pointer movement,
- mouse buttons and wheel through XTEST,
- clipboard read/write/watch through the X11 `CLIPBOARD` selection (`xclip`),
- media keys through the shared Linux uinput output when supplied.

Caption/title-bar manipulation is deliberately not advertised as a generic X11 capability because common mechanisms are window-manager specific rather than a portable EWMH operation.

## Testing

Run unit/integration tests with:

```bash
dotnet test tests/iKeyd.X11.Tests/iKeyd.X11.Tests.csproj
```

The `X11` GitHub Actions workflow starts Xvfb plus Openbox, providing both a real X server and an EWMH window manager. It then exercises real X11 clipboard, active-window/client-list/work-area state, focus, move/resize, maximize/restore, top-most, opacity and XTEST pointer operations against a real xterm window.

Changes to `iKeyd.Linux` also trigger the Wayland workflow so the shared evdev/uinput layer is regression-tested through both Linux backend paths.
