When your keyboard becomes part of your workflow, it should be as readable and reproducible as the rest of your setup.

Define behavior,

Describe remaps, layers, combos, and key behavior in a format you can actually read.

02 / COMPILE

Readable in.
Predictable out.

Compile the authoring DSL to the static JSON profile consumed by the runtime.

WHY IKEYD

Why put your keyboard in code?

01

Versionable

Keyboard behavior belongs in source control.

git diff config/hotkeySKG.ikeyd
02

Reviewable

See exactly what changed before you run it.

A = LT(NUM, Z) → A = LT(NAV, Z)
03

Shareable

Share the configuration, not screenshots of settings.

config/hotkeySKG.ikeyd
04

Understandable

Read what each key does without reverse-engineering a settings UI.

combo BASE[2,8] + BASE[1,1] = "fa"
